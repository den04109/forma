# Forma — конструктор персональных портфолио

Веб-платформа, в которой пользователь без навыков программирования создаёт одностраничное портфолио: выбирает шаблон, наполняет блоки, настраивает дизайн и публикует страницу по своей ссылке.

**Стек:** React + TypeScript, Vite, Tailwind CSS, React Router, Zustand, Framer Motion, Lucide, Supabase (Auth, PostgreSQL, Storage), dnd-kit, React Hook Form + Zod.

## Быстрый старт

Нужен Node.js 18 или новее.

```bash
npm install
cp .env.example .env     # затем заполните значения (см. ниже)
npm run dev              # http://localhost:5173
```

Другие команды: `npm run build` (проверка типов и сборка в `dist/`), `npm run preview` (локальный просмотр сборки).

## Настройка Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor** → выполните целиком файлы `supabase/migrations/0001_init_portfolios.sql` и затем `0002_restrict_published_reads.sql`. Он создаёт таблицу `portfolios`, индексы, триггеры, функцию проверки адреса `is_slug_available`, политики RLS, а также бакет `portfolio-images` с политиками Storage.
3. **Project Settings → API** → скопируйте `Project URL` и ключ `anon public` в `.env`:
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=...
   ```
   Секретный ключ `service_role` в клиентский код и `.env` этого проекта класть **нельзя**.
4. **Authentication → Providers → Email**: для разработки можно отключить «Confirm email». Если подтверждение включено, после регистрации пользователь увидит экран «Проверьте почту».
5. **Authentication → URL Configuration**: при деплое укажите адрес сайта в Site URL и Redirect URLs.

### Безопасность

- RLS включён: владелец читает и меняет только свои портфолио, публичные страницы читаются через функцию `get_published_portfolio` и только для статуса `published`. Авторизованный пользователь на уровне БД видит в таблице только свои записи. Черновики приватны.
- Адрес (`slug`) уникален; формат проверяется и в приложении, и ограничением в БД.
- Загрузка изображений: JPEG, PNG, WebP, GIF, до 5 МБ (проверка в приложении и в настройках бакета). Файлы пишутся только в папку `<user_id>/`. Перед загрузкой изображение уменьшается до 1600 px и сохраняется в WebP (GIF без изменений).
- Пользовательские ссылки фильтруются: допустимы только `http`, `https`, `mailto`, `tel` и якоря.

## Деплой

Приложение — SPA, поэтому хостингу нужно отдавать `index.html` для любых путей (иначе `/p/slug` даст 404 при прямом заходе). Уже добавлены `vercel.json` (Vercel) и `public/_redirects` (Netlify, Cloudflare Pages). Переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` задайте в настройках хостинга.

## Структура

```
src/
  app/router/           маршруты и защита приватных страниц
  components/           ui (Button, Input, ConfirmDialog), layout, shared
  features/
    auth/               форма входа/регистрации, authStore
    portfolios/         доступ к БД и Storage, список портфолио
    editor/             панели редактора, автосохранение, настройки блоков и дизайна
    publishing/         диалог публикации, проверка slug
  pages/                страницы маршрутов
  portfolio/
    blocks/             компоненты 10 типов блоков
    renderer/           PortfolioRenderer (общий для предпросмотра и публичной страницы)
    templates/          шаблоны и демо-данные
    types/              типы документа
  store/editorStore.ts  состояние редактора, история, статус сохранения
supabase/migrations/    SQL
```

Документ портфолио хранится в `portfolios.document` (JSONB): тема, SEO и массив блоков. Публичная страница `/p/:slug` и предпросмотр в редакторе используют один и тот же `PortfolioRenderer`.

## Возможности редактора

- Блоки: добавление, удаление, скрытие, перестановка перетаскиванием (в том числе клавиатурой).
- Настройки каждого блока справа; вкладка «Дизайн» — цвета, схемы, шрифт, размеры, скругления, кнопки, ширина, SEO.
- Оформление отдельного блока: шрифт, масштаб, выравнивание, отступы, цвета.
- Двойной щелчок по тексту в предпросмотре редактирует его на месте. В многострочных текстах доступна панель: жирный, курсив, размер и цвет выделенного фрагмента.
- Ручки изменения размера у фото и изображений проектов; панели можно растягивать мышью.
- **Экспорт сайта:** кнопка «Скачать» (в редакторе и на карточке в личном кабинете) создаёт один файл `index.html` с вёрсткой, стилями, используемыми шрифтами и изображениями. Его можно загрузить на любой хостинг. Если изображение не удалось встроить (например, из-за CORS), оно останется внешней ссылкой, о чём приложение предупредит.
- Отмена и повтор (`Ctrl+Z` / `Ctrl+Shift+Z`), автосохранение с задержкой 1 секунда, предпросмотр для компьютера и смартфона.

Разметка в многострочных текстах: абзацы разделяются пустой строкой, `**жирный**`, `*курсив*`, `{{#e03131|цветной}}`, `{{+|крупнее}}`, `{{-|мельче}}`.

## Известные ограничения

- Старые файлы в Storage при замене или удалении изображения не удаляются: после отмены действия ссылка должна остаться рабочей. Периодическую чистку лучше делать отдельной задачей через Storage API (Supabase не рекомендует удалять объекты прямым SQL).
- Свободное перемещение элементов по странице (как на холсте) не реализовано: страница намеренно остаётся адаптивной.
- Редактирование на месте доступно для основных текстов (заголовки разделов, Hero, «Обо мне», «Свой раздел»); остальные поля меняются в правой панели.
- Режим `contenteditable="plaintext-only"` требует Chrome/Edge или Firefox 136+.
- Первая версия не включает тарифы, свои домены, аналитику, многостраничность и админ-панель.

## Если что-то не работает

- **«relation portfolios does not exist» / ошибки RLS** — не выполнена миграция или выполнена не полностью.
- **Форма входа пишет, что Supabase не настроен** — пустой `.env` или не перезапущен `npm run dev`.
- **Не загружаются изображения** — проверьте, что бакет `portfolio-images` создан и в нём есть политики из миграции.
- **`/p/slug` открывается только с главной** — на хостинге не настроен фолбэк на `index.html`.

## Деплой на GitHub Pages

1. Создайте публичный репозиторий и отправьте в него проект (ветка `main`).
2. Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**: добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Каждый push в `main` запускает `.github/workflows/deploy.yml` (вкладка **Actions**). Сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`.
5. В Supabase (**Authentication → URL Configuration**) укажите этот адрес в Site URL и добавьте `https://<логин>.github.io/<репозиторий>/**` в Redirect URLs.

Прямые ссылки `/p/slug` работают за счёт копии `404.html` (GitHub Pages отдаёт её для неизвестных путей, приложение само разбирает адрес). Минус: такие страницы отдаются со статусом 404, что хуже для поисковиков и предпросмотра ссылок в мессенджерах. Для боевого использования лучше Vercel/Netlify или свой домен.
